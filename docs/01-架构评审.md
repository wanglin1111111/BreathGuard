# 架构评审意见：语音确认闭环的结构性假设问题

> **文档说明**：本文是团队架构评审记录，确立了"感知驱动并行决策"这一核心设计原则——语音确认从"必经门控"降为"辅助降级手段"，呼吸感知成为主决策通道。
> **代码对应**：`waveguard/edge/state_machine.py`（跌倒时按呼吸状态分叉 Zone 2/3/4）、`waveguard/edge/guardian.py`（呼吸驱动告警分级）。
>
> 提出人：团队成员
> 日期：2026-08-01
> 对象：护院鹅居家安全守护系统核心闭环设计

---

## 一、问题概述

项目文档将核心闭环定义为：

> **感知疑似 → AI 语音确认"您还好吗" → 老人应答则消警 / 无应答则升级告警子女**

这个闭环有一个隐含假设：**老人能够听见、理解并回应语音询问。**

在跌倒最危险的场景中，这个假设不成立：

| 真实场景 | 老人能回应吗 | 语音确认的作用 |
|---------|------------|-------------|
| 普通滑倒，人清醒 | 能 | 有用，可消警 |
| 跌倒后昏迷（脑震荡/脑出血） | 不能 | **白等，延迟救命** |
| 中风/脑缺氧 | 不能 | **白等** |
| 心脏骤停 | 不能 | **白等** |
| 癫痫发作后 | 不能 | **白等** |
| 呼吸道阻塞/窒息 | 不能 | **白等** |

**核心矛盾：最需要快速告警的场景，恰恰是语音确认失效的场景。**

---

## 二、当前架构分析

### 2.1 文档叙述 vs 实际实现

值得注意：测试报告中的三级告警逻辑实际上比"一句话定位"讲的更合理：

| 状态 | 告警级别 |
|------|---------|
| 有活动 | 正常 |
| 剧烈波动 + 静默 + **仍检出呼吸** | 二级告警（疑似跌倒但存活） |
| 剧烈波动 + 静默 + **呼吸消失** | 一级告警（最高级） |

**呼吸检测已经在做并行判断**，不依赖语音回应。但项目对外叙述时把"语音确认"包装成了核心闭环，反而把真正靠谱的"感知驱动决策"埋没了。

### 2.2 结构性缺陷

**缺陷一：语音确认是串行门控，不是并行辅助**

```
当前：感知异常 → 语音确认 → 等待 → 有回应? → 消警/告警
                              ↑
                         这一步阻塞了后续决策
```

语音确认应该是一个**并行信息通道**，而不是**串行门控**。老人不回应不等于出事了（可能没听见、不想理、耳朵不好），但呼吸异常几乎是硬指标。

**缺陷二：等待时间引入致命延迟**

如果语音确认后等待 N 秒才升级告警，这 N 秒在中风/心脏骤停场景中可能是生与死的区别。cardiac arrest 的黄金抢救窗口是 4 分钟，每延迟 1 分钟生存率下降 10%。

**缺陷三：叙述框架倒置了主次**

项目最大的技术亮点是 **CSI 无接触呼吸检测**（实测误差 0.2 次/分），这在养老监护领域是稀缺能力。但当前叙述把语音确认放在 C 位，呼吸检测反而成了配角。应该反过来。

## 三、改进建议

### 3.1 架构调整：感知驱动并行决策

```
感知异常 → 异常分类（呼吸状态 + 活动模式）
              ├── 呼吸正常 + 仅静止 → 语音确认（辅助降级）→ 回应则消警 / 无回应则提醒
              ├── 呼吸异常 → 二级告警（不等回应，立即通知子女）
              └── 呼吸消失 → 一级告警（立即拨打急救+通知子女）
```

**关键变化：**
1. 语音确认从"必经门控"降为"一条并行路径的辅助手段"
2. 呼吸状态成为主决策通道
3. 危险场景（呼吸异常/消失）不等语音回应，直接告警
4. 语音确认仅用于"呼吸正常但静止"这种低风险场景，用来区分"睡着了"和"需要关注"

### 3.2 叙述框架调整

**当前叙述**："不用摄像头也能守护独居老人 + AI 语音确认闭环"

**建议叙述**："非视觉呼吸感知驱动的居家守护——CSI 无接触检测呼吸与活动，AI 认知层做分级决策，语音确认仅作为低风险场景的辅助降级手段"

这样做的理由：
- 呼吸检测是真正有壁垒的技术（专利 + 实测数据）
- "语音确认"任何竞品都能做（调个 API 就行），不是差异化
- 评委看到"感知驱动决策"比看到"语音确认"技术含量高得多

### 3.3 AI 认知层提示词方向

```
输入：CSI 感知数据（活动强度、呼吸频率、呼吸状态）
     ↓
Qwen 推理：
  1. 活动模式分类（正常活动/剧烈波动后静止/长时间无活动）
  2. 呼吸状态评估（正常/异常/消失）
  3. 综合风险判断
     ↓
输出：风险等级 + 推荐动作
  - 正常 → 不动作
  - 低风险（静止但呼吸正常）→ 发起语音确认（辅助）
  - 中风险（呼吸异常）→ 二级告警，通知子女
  - 高风险（呼吸消失）→ 一级告警，通知子女 + 建议拨打120
```

## 四、对参赛评分的影响

| 评分维度 | 当前方案 | 调整后 | 变化 |
|---------|---------|-------|------|
| 技术实现-AI参与程度(15) | 语音确认=调TTS API，AI参与浅 | Qwen做时序推理+分级决策，AI参与深 | +5~7分 |
| 公益价值-解决问题重要性(10) | 语音确认不解决"无法回应"场景 | 感知驱动覆盖所有场景含昏迷 | +2~3分 |
| 创新价值(15) | "语音确认"无差异化 | "呼吸感知驱动决策"是专利级创新 | +3~5分 |
| 用户友好-场景适配(10) | 等待语音回应增加焦虑 | 危险场景直接告警，不折腾老人 | +2~3分 |

**预估总分提升：12~18分**
