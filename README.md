## 一、这是什么

**护院鹅**是一套面向独居老人的居家安全守护系统。它通过家用 WiFi 信号（CSI，信道状态信息）的无感感知，实时识别老人是否跌倒、呼吸是否正常，并结合老人的既往病史，用大模型（Qwen-plus）做出医学推理，给出分级告警决策。

一句话定位：

> WiFi 信号充满整个房间——人走动会让信号波动，呼吸时胸口起伏也会让信号规律变化。系统分析这些变化，就知道"有人没人""在动还是静止""呼吸正不正常"。

- **感知层**：ESP32-S3 收发节点提取 CSI（活动强度 + 呼吸频率）
- **边缘层**：FastAPI + SQLite + WebSocket，运行六区六级状态机
- **认知层**：Qwen-plus 大模型医学推理 + 病历个性化，规则版降级保底
- **交互层**：老人端语音确证 + 子女端实时 Web 看板

---

## 二、它解决了什么问题

**3.1 亿老人，1.2 亿独居，每年约 30% 会跌倒。跌倒后无人发现，是独居老人最大的恐惧。**

现有方案都有死角：

| 方案 | 问题 |
|------|------|
| 摄像头 | 进不了卫生间和卧室——恰恰是跌倒高发区，且泄露隐私 |
| 防跌手环 | 洗澡时摘下——恰恰洗澡时最容易摔倒 |
| 紧急按钮 | 跌倒后躺在地上够不着 |

**老人最需要帮助的地方，恰恰是现有方案覆盖不到的地方。**

护院鹅的关键差异在于：信号穿墙覆盖全屋（含卫生间、卧室），无需穿戴、无需摄像头、无需老人操作，并且能感知**呼吸**这一其他方案给不了的关键维度。

## 三、核心能力

### 🫁 无接触呼吸检测 —— 最关键的能力

老人静止时，系统通过 WiFi 信号感知呼吸频率。不贴传感器，不戴手环，信号穿过空气就能"听"到一呼一吸。

- 呼吸正常 → 老人可能只是坐着休息
- 呼吸加快 → 可能缺氧
- 呼吸消失 → 可能心跳骤停，立即急救

> 传统方案只能告诉你"摔倒了"。护院鹅能告诉你"摔倒了，而且呼吸异常"——这两条信息加在一起，判断准确度完全不同。

### 🏥 病历个性化守护 —— 因人施守

同样的跌倒，不同的老人，不同的处理。子女录入病史后，系统自动调整检测与告警策略（详见[第七节](#七病历个性化守护)）。

### 🔔 六区六级分级告警 —— 不是非黑即白

从"系统异常"到"紧急救援"，六个区逐级升降，呼吸在变化，等级在跟踪。

### 🎙️ AI 语音确证 —— 减少误报

仅在"跌倒 + 呼吸正常"时启动语音问候；呼吸异常的场景跳过语音直接告警——因为缺氧昏迷时老人根本无法回应。

### 🛡️ 护家模式 —— 一套硬件两种守护

外出/睡眠时切换防盗模式，异常运动联动告警。

## 四、系统架构

```
┌─────────────────────────────────────────────────────────┐
│  交互层    老人端(语音确证)  /  子女端 Web(实时看板)       │
├─────────────────────────────────────────────────────────┤
│  认知层    Qwen-plus 医学推理 + 病历个性化 + 规则版降级    │
│           输入: 结构化语义事件   输出: 分级告警 + 推理理由   │
├─────────────────────────────────────────────────────────┤
│  边缘层    六区六级状态机 + Zone 升降级引擎 + 语音确证      │
│           FastAPI + SQLite(本地闭环) + WebSocket 广播     │
├─────────────────────────────────────────────────────────┤
│  感知层    WiFi CSI 感知系统 (TX 发射 / RX 采集)           │
│           活动强度 + 呼吸频率  →  结构化事件流            │
└─────────────────────────────────────────────────────────┘
```

**关键设计**：Qwen 只接收**结构化事件**（如"跌倒 + 呼吸 28 次/分 + 心梗史"），绝不接触原始 CSI 波形。原始数据不出家门，隐私有保障，未来感知硬件升级上层零改动。

### 数据流

```
剧本播放器 / 硬件轨          边缘服务 edge/                   子女端 web/
逐秒活动强度+呼吸样本   →   状态机判定事件              →   WebSocket 实时:
                          (presence/motion/fall/breathing)     · 守护状态卡变色
                          → SQLite 入库                        · 活动强度曲线
                          → guardian 派生分级告警              · 呼吸频率显示
                          → WebSocket 广播                     · Zone 级别
                                                              · 告警时间线
```

三种数据入口走**完全相同的下游链路**：`csi_live`（硬件轨）/ `dataset_replay`（模拟轨）/ `demo_inject`（演示注入），未来硬件接入零改动。

## 五、核心概念：六区六级状态机

这是整个系统的心脏。所有守护决策都围绕这六个区展开：

| Zone | 名称 | 颜色 | 触发条件 | 系统响应 |
|------|------|------|---------|---------|
| **-1** | 灰区 | ⚪ | 设备故障 / 断网 | 暂停判断，推送设备告警 |
| **0** | 绿区 | 🟢 | 正常活动 / 呼吸正常 | 安静守护，持续监测 |
| **1** | 黄区 | 🟡 | 静止太久 / 呼吸加快 | 提升警觉，30 分钟复查 |
| **2** | 橙区 | 🟠 | 跌倒 + **呼吸正常** | AI 语音确认，超时升级 |
| **3** | 红区 | 🔴 | 跌倒 + **呼吸异常** | 立即通知子女，不等语音 |
| **4** | 黑区 | ⚫ | **呼吸消失** | 紧急救援，建议拨打 120 |

### 核心架构思想：呼吸感知驱动决策

```
旧方案：跌倒 → 直接告警 → 语音确认"您还好吗"
         ↑ 问题：老人昏迷/心脏骤停时根本无法回应语音

新方案：跌倒 → 检查呼吸 → 分级处理
         ├── 呼吸正常 → 语音确认（Zone 2，超时自动升级）
         ├── 呼吸异常 → 立即告警子女，不等语音（Zone 3）
         └── 呼吸消失 → 紧急救援，建议拨打 120（Zone 4）
```

### Zone 自动升降级引擎

状态机内置完整的运行时转换逻辑（基于时间推进 + 呼吸变化）：

| 触发类型 | 转换规则 | 说明 |
|---------|---------|------|
| 超时升级 | Zone 2 → Zone 3 | 语音确认 90s 无回应（高危人群 60s） |
| 超时升级 | Zone 3 → Zone 4 | 告警推送后 5 分钟子女未确认 |
| 呼吸恶化升级 | Zone 1 → Zone 3 | 呼吸从"加快"恶化到"节律异常" |
| 呼吸恶化升级 | Zone 2 → Zone 3 | 语音确认期间呼吸恶化 |
| 呼吸恶化升级 | Zone 2/3 → Zone 4 | 呼吸消失 |
| 呼吸恢复降级 | Zone 4 → Zone 3 | 呼吸恢复（维持告警不解除） |
| 复查降级 | Zone 1 → Zone 0 | 30 分钟复查呼吸恢复正常 |
| 病历覆盖 | Zone 3 停留超限 → Zone 4 | 高血压病史：Zone 3 超 10 分钟自动升级 |

> **降级不等于解除**：Zone 4→3 是"呼吸恢复了但仍然危险"，告警维持；Zone 3 不会因呼吸恢复自动降到 0，必须子女端手动确认。

## 六、呼吸五级分类

基于医学 OSINT 研究（脑缺氧与呼吸变化）建立的五级分类，是认知层决策的基准：

| 等级 | 代码值 | 名称 | 判断标准 | 缺氧阶段 | 告警级别 |
|------|--------|------|---------|---------|---------|
| B0 | `normal` | 正常 | 12–20 次/分，节律整齐 | 无 | 不告警 |
| B1 | `elevated` | 加快 | >20 次/分 | 轻度缺氧 | 关注（warning） |
| B2 | `irregular` | 不整 | 节律异常 | 中度缺氧 | 关注（warning） |
| B3 | `shallow` | 浅慢 | <8 次/分 / 潮式呼吸 | 重度缺氧 | 紧急（emergency） |
| B4 | `lost` | 消失 | 无法检测到呼吸信号 | 呼吸停止 | 紧急（emergency） |

- **恶化判断**：`severity(new) > severity(last)` 即为恶化，触发升级
- **恢复判断**：`severity(new) < severity(last)` 即为恢复，触发降级

## 七、病历个性化守护

### 因人施守

子女录入老人的既往病史与用药情况后，系统自动调整检测与告警策略。**同样的跌倒，不同的老人，不同的处理：**

| 病史 | 跌倒处理调整 | 原因 |
|------|------------|------|
| **心梗 / 心律失常** | 跳过语音，直接告警 Zone 3 | 心源性恶化极快，20–30 秒呼吸可能停止 |
| **脑梗 / TIA** | 语音超时从 90s 缩短到 45s | 可能清醒但无法回应 |
| **癫痫** | 识别发作模式，超时 60s | 发作期呼吸可能暂停 >30s |
| **糖尿病** | 排查低血糖，超时 60s | 低血糖可致意识丧失 |
| **高血压** | Zone 3 超 10 分钟自动升级 | 高血压急症可致跌倒 |
| **帕金森** | 标注神经源性 | 体位性低血压 / 步态异常 |
| **多重用药（≥4 种）** | 标注药源性 | 药物副作用致跌倒 |

### 开放式疾病注册

预设 8 种疾病之外，支持**自定义疾病注册**——子女可注册任意疾病及其特征、对跌倒/呼吸的影响、告警建议、语音超时覆盖：

```python
from edge.medical import CustomDisease, register_disease

register_disease(CustomDisease(
    code="copd",
    name="慢性阻塞性肺病",
    category="呼吸系统",
    breathing_impact="呼吸基线不同，正常定义需放宽",
    advice=["关注呼吸频率变化", "如出现潮式呼吸立即就医"],
    voice_timeout_override=60,
))
```

## 八、快速开始

### 环境要求

- Python 3.10+
-（可选）阿里云百炼 DashScope API Key —— 用于激活 Qwen 认知层；不配置则自动降级为规则版，功能不受影响

### 三步跑起来

```bash
# 0. 安装依赖（首次）
pip install -r requirements.txt

# 1. 启动边缘服务（窗口一，保持运行）
cd waveguard
python run_edge.py

# 2. 浏览器打开子女端
#    http://127.0.0.1:8000

# 3. 播放剧本（窗口二）
cd waveguard
python -m replay.player                      # 默认剧本 day_fall
```

播放开始后，子女端会依次出现：🚪 有人在家 → 🏃 正常活动 → 😴 静息 → 🚨 **疑似跌倒告警**（状态卡变色脉冲 + AI 判断理由）。

### 激活 Qwen 认知层（可选）

设置环境变量即可启用大模型医学推理：

```bash
# Linux / macOS
export DASHSCOPE_API_KEY="sk-your-key-here"

# Windows PowerShell
$env:DASHSCOPE_API_KEY="sk-your-key-here"

# Windows CMD
set DASHSCOPE_API_KEY=sk-your-key-here
```

未配置时，系统自动降级为内置规则版（同样含病历个性化逻辑），告警决策依然准确。

### 常用命令

```bash
python -m replay.player --scenario day_fall_abnormal --speed 5   # 指定剧本 + 放慢
python -m replay.player --url http://127.0.0.1:8000              # 指定服务地址

# 重置一场演示（清库 + 重置状态机）
curl -X POST http://127.0.0.1:8000/api/reset
```

### 信号测试播放器（Windows 一键菜单）

项目附带的 `信号测试播放器.bat` 提供交互式菜单，可一键播放各类测试信号：

```
[1] 静止状态          [2] 正常运动        [3] 剧烈运动
[4] 呼吸均匀          [5] 呼吸异常        [6] 跌倒+呼吸正常(Zone 2)
[7] 跌倒+呼吸异常(Zone 3)  [8] 心梗老人跌倒  [9] 呼吸消失(Zone 4)
```

> 所有测试信号均基于真实硬件实测数据特征模拟，与硬件轨走完全相同的下游链路。

## 十、API 接口文档

### 状态与查询

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/status` | 当前守护状态（在场、Zone 级别） |
| `GET` | `/api/events?limit=50` | 最近事件列表 |
| `POST` | `/api/reset` | 重置演示（清库 + 重置状态机） |

### 病历管理

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/profile` | 获取老人健康档案 |
| `POST` | `/api/profile` | 保存健康档案（病史 / 用药 / 起居） |

### 语音确证

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/voice-confirm` | 当前语音确证状态 |
| `POST` | `/api/voice-confirm/respond?answer=ok` | 老人回应：`ok`=没事 / `help`=求助 |

### 告警与护家模式

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/family/confirm` | 子女确认收到告警，阻止 Zone 3→4 超时升级 |
| `GET` | `/api/guard-mode` | 获取护家模式状态 |
| `POST` | `/api/guard-mode/toggle` | 远程开关护家模式（访客模式） |

### 开放式疾病注册

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/diseases` | 列出所有疾病策略（预设 + 自定义） |
| `POST` | `/api/diseases` | 注册自定义疾病 |
| `DELETE` | `/api/diseases/{code}` | 移除自定义疾病 |
| `GET` | `/api/diseases/{code}/strategy` | 获取指定疾病的告警策略 |

### 实时通信

| 协议 | 路径 | 说明 |
|------|------|------|
| `WS` | `/ws` | WebSocket 广播：事件 / 告警 / 样本 / 语音确证 / 模式切换 |

## 十三、隐私设计

护院鹅的隐私优势不是"天生无风险"，而是**用架构把风险压到最低**：

| # | 原则 | 落地方式 |
|---|------|---------|
| 1 | **边缘计算** | CSI 解算 + AI 推理全在本地，数据不上云 |
| 2 | **最小化产出** | 只输出"跌倒 / 呼吸异常"事件布尔量，不留存连续轨迹、不还原姿态、不识别身份 |
| 3 | **数据私有** | 本地 SQLite 存储，用户可删除、不训练、不共享 |
| 4 | **认知层隔离** | Qwen 只接收结构化语义事件，绝不接触原始 CSI 波形 |
| 5 | **功率控制** | 可调低 AP 发射功率，减小信号溢出 |
| 6 | **知情同意** | 对老人和家属明确告知感知方式 |

> 诚实口径：不拍人脸、不录视频、只在发生时才上报。相比摄像头方案产出可被任何人回看的高敏感人脸视频，护院鹅的暴露面更小。

## 十四、护家模式（防盗监测）

护院鹅的两项核心感知能力——**移动物体状态检测**和**呼吸频率检测**——是整个系统的技术底座。除老人守护外，同一套硬件可扩展防盗监测：

- 无人 / 睡眠静默超过阈值（默认 5 分钟）后自动进入护家模式
- 防盗模式下检测到持续异常运动 → 触发疑似入侵告警
- 可联动摄像头做物体形态确认
- 子女可远程手动开关（访客到访时关闭，离开后恢复）

```bash
curl -X POST http://127.0.0.1:8000/api/guard-mode/toggle
```

## 十五、项目路线图

当前重点：老年人跌倒守护与睡眠呼吸监测的垂直应用。未来同一套感知能力可扩展更多场景：

| 方向 | 能力 | 价值 |
|------|------|------|
| **全天候呼吸早干预** | 白天活动 + 夜间睡眠呼吸监测 | 心脏病 / 癫痫 / 脑梗等突发恶疾早期干预 |
| **健康趋势追踪** | 长期呼吸数据沉淀 | 发现呼吸频率渐变趋势，从"急救"走向"预防" |
| **睡眠呼吸暂停筛查** | 夜间呼吸节律监测 | 发现很多人自己都不知道的睡眠呼吸暂停征兆 |
| **反诈行为预警** | 活动模式长期趋势分析 + AI 推理 | 捕获被骗前兆信号（作息紊乱、异常时段活动、社交频率骤降），填补孤独这一骗子最大可乘之机。详见 [反诈研究](docs/04-反诈研究.md) |

**两项感知能力，多个垂直场景。当前做深老年人跌倒守护，未来逐步扩展更多想象空间。**

## 十七、⚠️ 安全须知

> **开源 / 提交到 GitHub 前，必须先清除密钥！**

`edge/config.py` 中通过环境变量读取 API Key：

```python
QWEN_API_KEY = os.environ.get("DASHSCOPE_API_KEY", "<fallback>")
```

**请确保**：

1. **不要把真实 API Key 硬编码进代码或写入任何默认值**
2. 检查 `config.py` 的 fallback 默认值是否为占位符（如 `"sk-your-key-here"`），而非真实密钥
3. 提交前确认 `.gitignore` 已忽略 `waveguard.db`、`.env` 等本地文件
4. 若历史提交中已泄露密钥，请在云控制台**立即吊销并重新生成**

建议在仓库根目录添加 `.env.example`：

```bash
# 复制为 .env 并填入真实 Key
DASHSCOPE_API_KEY=sk-your-key-here
```
